# fastpanel-db — базы данных в FastPanel от имени пользователя панели

Работает через REST API панели под обычным пользователем. Не использует root, не использует
`mogwai`, не требует админа панели.

```bash
SCRIPT="${CLAUDE_PLUGIN_ROOT}/skills/fastpanel-db/scripts/fastpanel_db.py"

python3 "$SCRIPT" list [-A ИМЯ]              # базы, видимые аккаунту
python3 "$SCRIPT" servers [-A ИМЯ]           # серверы БД и доступные кодировки
python3 "$SCRIPT" add ИМЯ [-A ИМЯ] [опции]   # создать базу, если её нет
```

Опции `add`:

| Опция | Значение |
|---|---|
| `--db-user LOGIN` | логин пользователя БД (по умолчанию — имя базы) |
| `--server mysql\|pg\|pg15` | сервер БД; `pg15` определяется по порту 5433 (по умолчанию `mysql`) |
| `--charset CS` | кодировка: `utf8mb4` (по умолчанию), `utf8`, `cp1251`, `latin1` — список берётся из `GET /api/charsets` и проверяется до создания |
| `--site DOMAIN` | привязать базу к сайту с этим доменом (панели передаётся числовой site id) |
| `--wait N` | сколько секунд ждать реального появления базы (по умолчанию 60) |
| `--no-prompt` | не спрашивать в терминале; при занятом имени просто выйти с кодом 3 |

Примеры:

```bash
python3 "$SCRIPT" add shop_main -A work --site shop.example.com
python3 "$SCRIPT" add analytics -A personal --server pg15
```

## Поведение `add`

1. Логин пользователя панели → Bearer-токен (из кеша, если не протух).
2. `GET /api/databases?offset=&limit=` — если база с таким именем уже есть, печатает
   `exists:` и выходит с кодом 0. Ничего не пересоздаёт и не трогает.
3. Иначе: проверяет кодировку, выбирает сервер (`GET /api/databases/servers`), берёт свой
   `owner_id` из `GET /api/users` по логину из токена (`/api/users/me` на панели нет),
   генерирует пароль пользователя БД и делает `POST /api/databases`.
4. Панель создаёт базу асинхронно — скрипт ждёт, пока она реально появится в списке.
5. Доступы пишутся в `~/.config/fastpanel/databases/<аккаунт>/<имя>.env` (`600`).
   **Пароль БД в stdout не печатается** — только путь к файлу и логин. Если пользователю
   нужен пароль, он смотрит файл сам; не выводи его в чат.

## Имя занято другим пользователем панели

Панель может ответить `{"errors": {"name": "База данных '...' уже существует"}}`: имя занято
на сервере БД, но самой базы нет в списке этого аккаунта — значит она заведена под другим
пользователем панели, доступа к ней нет и трогать её нельзя.

Скрипт в этом случае выходит с кодом **3** и печатает несколько свободных имён (с префиксом
логина и с номером; кандидаты сверены со списком баз аккаунта).

**Что делать агенту:** передать пользователю, что база с таким именем уже создана из-под
другого пользователя панели, и предложить выбор — покажи напечатанные варианты списком
(инструментом вопроса с вариантами) и обязательно оставь возможность ввести своё название.
Имя сам не выбирай и базу под другим именем молча не создавай. После ответа запусти
`add` заново с выбранным именем.

Если скрипт запускает человек в терминале, он сам показывает меню: номер варианта,
пункт «type another name» или сразу введённое имя, `0` — отмена.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | база создана или уже существовала |
| 1 | ошибка: нет доступов, кривые права, не выбран аккаунт, не вышел логин, панель отказала |
| 3 | имя занято другим пользователем панели — нужен выбор пользователя |

## Отчёт пользователю

Коротко: создана база или уже была, под каким аккаунтом, на каком сервере, куда положены
доступы. Без паролей.

Доступы и правила обращения с паролем панели: `${CLAUDE_PLUGIN_ROOT}/SETUP.md`. Коротко:
один файл `~/.config/fastpanel/config.json` (`600`), **читать его нельзя**
(`cat`/`grep`/`head` по `~/.config/fastpanel/` запрещены), пароль в чат не попадает.
Если файла нет — скрипт печатает инструкцию по настройке, покажи её целиком и остановись.
