# fastpanel-dns — DNS-домены в FastPanel

Работает через REST API панели, как остальные инструменты плагина.

```bash
SCRIPT="${CLAUDE_PLUGIN_ROOT}/skills/fastpanel-dns/scripts/fastpanel_dns.py"

python3 "$SCRIPT" accounts [-A ID_АККАУНТА]          # DNS-аккаунты панели: id, тип, имя
python3 "$SCRIPT" list [-A ID_АККАУНТА]              # DNS-домены: id, сайт, на каком DNS-аккаунте, почтовый сервис
python3 "$SCRIPT" show ДОМЕН [-A ID_АККАУНТА]        # один DNS-домен: владелец, DNS-аккаунт, поля панели
python3 "$SCRIPT" records ДОМЕН [-A ID_АККАУНТА]     # записи домена, как их держит панель
python3 "$SCRIPT" record-add ДОМЕН ИМЯ ТИП ЗНАЧЕНИЕ [-A ID_АККАУНТА] [--priority N]   # добавить запись, если такой нет
python3 "$SCRIPT" record-edit ДОМЕН ИМЯ ТИП --to НОВОЕ [--from ТЕКУЩЕЕ] [-A ID_АККАУНТА]   # изменить значение записи
python3 "$SCRIPT" record-delete ДОМЕН ИМЯ ТИП [--content ЗНАЧЕНИЕ] [--confirm КОД] [-A ID_АККАУНТА]   # удалить запись
python3 "$SCRIPT" mailto ДОМЕН СЕРВИС [-A ID_АККАУНТА]   # привязать почту домена к сервису (google, local)
python3 "$SCRIPT" add ДОМЕН [-A ID_АККАУНТА] [--dns-account КАКОЙ] [опции]   # создать DNS-домен, если его нет
python3 "$SCRIPT" sync ДОМЕН [-A ID_АККАУНТА]        # синхронизировать записи домена с его DNS-аккаунтом
python3 "$SCRIPT" delete ДОМЕН [--from-provider] [--confirm КОД] [-A ID_АККАУНТА]   # удалить DNS-домен
```

DNS-аккаунт — это подключённый к панели внешний DNS-провайдер (FASTDNS, Cloudflare,
DigitalOcean) со своим токеном. Заводит его пользователь сам, в панели: «Настройки» →
«DNS-аккаунты». Токены провайдеров панель не отдаёт, инструмент их не видит.

Опции `add`:

| Опция | Значение |
|---|---|
| `--dns-account NAME` | на какой DNS-аккаунт завести домен: имя или id из `accounts`; обязательна, если DNS-аккаунтов на панели несколько |
| `--site DOMAIN` | сайт, к которому привязан DNS-домен (по умолчанию — сайт с тем же именем); владелец DNS-домена берётся панелью от сайта |
| `--no-site` | поле сайта оставить пустым: DNS-домен без сайта; нужен `--ip` |
| `--ip IP` | ip для записей новой зоны, можно несколько раз (по умолчанию — ip сайта); панель принимает только ip самого сервера; если зона у провайдера уже есть, не применяется |
| `--wait N` | сколько секунд ждать появления домена (по умолчанию 60) |

Примеры:

```bash
python3 "$SCRIPT" add example.com --dns-account fastDNSfree
python3 "$SCRIPT" add example.com --dns-account 2 --site shop.example.com
python3 "$SCRIPT" add example.com --dns-account 2 --no-site --ip 203.0.113.10
python3 "$SCRIPT" sync example.com
```

## Что спросить до `add`, `sync` и `delete`

**Сначала скажи, где.** До запуска команды, которая что-то создаёт или меняет, явно напиши
пользователю: id аккаунта, домен, DNS-аккаунт и что будет сделано.
Подробно — `${CLAUDE_PLUGIN_ROOT}/SETUP.md`, раздел «Сначала скажи, где».

Если DNS-аккаунтов на панели несколько и пользователь не назвал, на какой заводить домен, —
без `--dns-account` скрипт выйдет с кодом **5** и напечатает их список. Покажи вариантами
(инструментом вопроса), сам не выбирай.

Сайта с именем домена нет — скрипт ничего не создаёт и говорит об этом. Сайт у DNS-домена —
рекомендация, а не требование: без сайта домен заводится с `--no-site --ip IP` (ip сервера,
чужой панель отклоняет: «Ip не принадлежит серверу»). К другому сайту привязывай через
`--site`, только если пользователь его назвал. Владельцем домена без сайта панель ставит
того, от чьего имени пришёл запрос (у администратора — user id 1); проверь через `show`.

## Поведение `add`

1. `GET /api/dns/domains` — если DNS-домен с таким именем уже есть, печатает `exists:` и
   выходит с кодом 0. Ничего не трогает и на другой DNS-аккаунт не переносит.
2. Иначе: выбирает DNS-аккаунт (`GET /api/dns/account`), находит сайт
   (`GET /api/sites/simple`, `GET /api/sites/<id>`), берёт его ip и делает
   `POST /api/dns/domains` — так же, как форма «Новый домен» в панели. С `--no-site` сайт
   не ищется и в запрос не попадает (проверено на живой панели).
3. Панель создаёт домен в очереди — скрипт ждёт, пока он появится в списке и освободится.

Зоны у провайдера ещё нет — панель заводит её со стандартным набором записей на переданный
ip. Зона у провайдера уже есть — панель показывает её существующие записи, переданный ip в
них не попадает (проверено на FASTDNS). Кириллические имена принимаются и переводятся в
punycode. После `add` покажи пользователю `records`.

## Поведение `sync`

`PUT /api/dns/domains/<id>/refresh` — кнопка «Синхронизировать» в списке DNS-доменов
панели. Скрипт ждёт, пока домен освободится. В какую сторону панель сводит записи (свои —
провайдеру или наоборот), по API не видно: **если у провайдера есть записи, которых нет в
панели, предупреди пользователя до запуска** и не запускай `sync` по всем доменам подряд без
его просьбы.

## Поведение `record-add`

`POST /api/dns/domain/<id>/records` с телом `{"name": "test", "type": "TXT", "content": "test"}`
— форма «Новая запись» на странице DNS-домена. Запись сразу уходит в зону у провайдера.

Имя — как в форме панели: `test` для `test.example.com`. Запись с тем же типом, именем и
значением уже есть — печатает `exists:` и ничего не меняет; отличается хоть значение —
добавляет вторую запись рядом, существующую не заменяет. Проверено на живой панели для TXT.
`--priority`, `--weight`, `--port` уходят в запрос одноимёнными полями — так они называются в
ответе `records`, на запись не проверялось; имя для корня домена (`@`) тоже не проверялось.

## Поведение `record-edit`

`PUT /api/dns/domain/records/<id записи>` с телом
`{"name": "test.example.com.", "type": "TXT", "content": "новое"}` — сохранение формы записи.
Имя уходит полным, с точкой, как его отдаёт `records`. Изменение сразу уходит провайдеру.

```bash
python3 "$SCRIPT" record-edit ДОМЕН ИМЯ ТИП --to НОВОЕ [--from ТЕКУЩЕЕ] [--priority N] [-A ID_АККАУНТА]
```

Запись ищется по имени и типу. Таких несколько — нужен `--from` с текущим значением, иначе
скрипт откажет и перечислит их. **Запись одна — меняет её сразу, без `--from`.** Новое
значение совпадает с текущим — `unchanged:`. Проверено на живой панели для TXT; приоритет,
вес и порт существующей записи скрипт переносит в запрос — на запись не проверялось.

## Поведение `record-delete`

`DELETE /api/dns/domain/records/<id записи>` — кнопка «Удалить» у записи. Необратимо, запись
сразу пропадает из зоны у провайдера.

```bash
python3 "$SCRIPT" record-delete ДОМЕН ИМЯ ТИП [--content ЗНАЧЕНИЕ] [--confirm КОД] [-A ID_АККАУНТА]
```

**Перед каждым удалением — проверка, это обязательно**, как у `delete`. Без `--confirm`
скрипт ничего не трогает: печатает сервер, аккаунт, домен, саму запись и код. Покажи вывод
пользователю, удаляй только после его ответа — той же командой с `--confirm КОД`. Код
привязан к этой записи и её значению; запись изменилась — скрипт откажет. Записей с таким
именем и типом несколько — нужен `--content`. Показ проверен на живой панели, само удаление
скриптом не запускалось (запрос снят с интерфейса панели).

## Проверочных запусков у `record-add` и `record-edit` нет

Обе команды меняют зону с первого вызова. Не запускай их «посмотреть, что скрипт откажет»:
состояние записей могло измениться в панели, и вместо отказа получится правка. Сначала
`records`, потом команда — и только та, о которой просил пользователь.

## Поведение `mailto`

`PUT /api/dns/domains/<id>/mailto` с телом `{"mail_to": "СЕРВИС"}` — выбор почтового сервиса
на странице DNS-домена в панели. Панель сама переписывает почтовые записи домена: с `google`
MX становится `smtp.google.com`, в SPF появляется `include:_spf.google.com` (видно по
записям после смены в панели). Значения, которые встречаются у доменов: `google` и `local`
(по умолчанию у нового домена, даже если MX в зоне провайдера смотрит на другой сервис).
Другие значения скрипт не проверяет — передаёт как есть, решает панель. Скриптом команда на
живой панели не запускалась.

До запуска покажи пользователю текущие MX и TXT домена (`records`) и скажи, что они будут
переписаны; после — покажи `records` снова. Сам сервис не выбирай.

## Поведение `delete`

`DELETE /api/dns/domains/<id>?removeFromProvider=true|false` — кнопка «Удалить» в списке
DNS-доменов панели. Удаление необратимо. Сайт, к которому привязан домен, не трогается.

**Перед каждым удалением — проверка, это обязательно.** Без `--confirm` скрипт ничего не
трогает: печатает сервер, аккаунт, владельца, домен, его DNS-аккаунт, сайт, все записи
домена, что было бы удалено, и код подтверждения. Покажи этот вывод пользователю и спроси
одним вопросом: удалять только из панели или вместе с зоной у провайдера. Удаляй только
после его ответа: та же команда с `--confirm КОД`. Код привязан к домену, его записям и
выбору про провайдера; изменилось что-то после показа — скрипт откажет, запусти показ
заново. Сам не выбирай.

| Вызов | Что удаляется |
|---|---|
| `delete ДОМЕН --confirm КОД` | DNS-домен в панели; зона с записями у провайдера остаётся |
| `delete ДОМЕН --from-provider --confirm КОД` | DNS-домен в панели и его зона со всеми записями у провайдера |

С `--confirm` скрипт ждёт, пока домен исчезнет из списка (`--wait N`, по умолчанию 60 секунд), и
печатает `deleted:`. Вместе с сайтом DNS-домен удаляет `fastpanel-sites delete --dns` /
`--dns-provider`.

## Чего инструмент не делает

Перенос существующего DNS-домена на другой DNS-аккаунт и смена его владельца — пока только
в панели.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | сделано, домен или запись уже были, или `delete` / `record-delete` без `--confirm` показал, что удалил бы |
| 1 | ошибка: нет доступов, не выбран аккаунт, не вышел логин, нет сайта, панель отказала |
| 5 | DNS-аккаунтов на панели несколько, а `--dns-account` не задан — спроси пользователя |

## Отчёт пользователю

Коротко: домен создан или уже был, на каком сервере, на каком DNS-аккаунте, к какому сайту
привязан.

Доступы и правила обращения с логином, паролем и токеном панели:
`${CLAUDE_PLUGIN_ROOT}/SETUP.md`. Коротко: один файл `~/.config/fastpanel/config.json`
(`600`), **читать его и кеш токена `~/.cache/fastpanel/` нельзя**; логин, пароль и токен в
чат не попадают — в выводе они заменены на `***`.
При ошибке настройки направь человека к INSTALL.md; диагностика остаётся локально, агент её не читает.
