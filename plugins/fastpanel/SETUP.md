# Доступы к панели (общее для всех инструментов fastpanel)

Все инструменты плагина читают один файл: `~/.config/fastpanel/config.json`, режим `600`,
каталог `700`. Путь переопределяется переменной `FASTPANEL_CONFIG`.

```json
{
  "url": "panel.example.com",
  "insecure": false,
  "accounts": [
    {"login": "...", "password": "...", "label": "рабочий"},
    {"name": "second", "login": "...", "password": "...", "url": "panel2.example.com"}
  ]
}
```

- `url` — хост панели; достаточно хоста, `https://` подставляется сам, суффикс `/api`
  инструменты добавляют одинаково для любой панели. Нестандартный порт — в хосте
  (`panel.example.com:8888`). Полный URL и лишний `/api` на конце тоже принимаются.
- `insecure: true` — только при самоподписанном сертификате панели.
- Адрес панели — только `https`: по `http` логин и пароль ушли бы открытым текстом, скрипт
  откажется работать. Редиректы не выполняются — токен не уходит на чужой адрес.
- Логин — секрет, аккаунт им не называется. Имя аккаунта скрипт делает сам: хеш вида
  `acc-1a2b3c4d` от адреса панели и логина (с локальной солью, по хешу логин не подобрать).
  Id постоянен, пока не меняются адрес, логин и локальная соль. Он идёт в `--account`
  и вывод `fastpanel_accounts.py list`; URL, name и label в этом выводе отсутствуют.
- Файлы, оставшиеся от прежних версий с логином в названии, скрипт при запуске переводит на
  новое имя сам: `token-<логин>` удаляет (это кеш), `databases/<логин>/` переименовывает.
- Поле `name` — локальный псевдоним для человека, не передавай его агенту. Человек
  может получить соответствующий id командой `fastpanel_accounts.py account-id -A ПСЕВДОНИМ`.
  Псевдоним не должен содержать логин. Старые локальные обращения по name поддерживаются.
- Аккаунту можно задать свой `url` — это перебивает общий.

## Правила обращения с логином, паролем и токеном

**Логин и пароль панели и полученный по ним токен не появляются ни в аргументах команд, ни
в выводе, ни в переписке.** Скрипты читают их сами. Доступы авторизации уходят на `/login`
собственной панели, токен — в заголовке запросов к ней. Имена целевых пользователей
внутри процесса передаются этой же панели для создания пользователя и работы с SSH-ключами.

- Скрипт откажется работать, если права шире `600` или файл принадлежит не тебе.
- Токен кешируется в `~/.cache/fastpanel/token-<аккаунт>` (`600`) и переиспользуется, пока
  жив; пароль трогается только когда токен протух. При 401 — один автоматический перелогин.
- Свободный вывод скриптов (stdout и stderr) проходит через скрабер: логин, пароль и токен
  заменяются на `***`. Это касается и данных панели: корень сайта выглядит как
  `/var/www/***/data/www/...`, имя базы с логином — как `***_main`. `***` в выводе — не
  ошибка; не пытайся восстановить, что под ним.

**Агенту нельзя читать файлы в `~/.config/fastpanel/` и `~/.cache/fastpanel/` (`cat`, `grep`,
`head`, `echo`, Read и любым другим способом), обращаться к панели в обход скриптов и просить
пользователя продиктовать логин или пароль.** При ошибке скрипт выдаёт только JSON
с фиксированным code. Подробности остаются локально в `diagnostics/last-error.json`
в каталоге конфига (`700`, файл `600`); агент их не читает и не пересылает.
Для первичной настройки направь человека к INSTALL.md, настройку он выполняет сам.

Запрет не только на словах: хук плагина (`hooks/guard.py`, PreToolUse) отклоняет вызовы
Read, Edit, Write, Grep, Glob и Bash, которые лезут в эти каталоги или подключают
`fastpanel_api` в обход скриптов плагина. Отказ хука — не сбой: не ищи обходной путь, скажи
пользователю, что именно нужно поменять в конфиге, он сделает это сам в своём терминале.
Ни у скриптов, ни у хука нет флага или переменной, которые это отключают.

`fastpanel-accounts add` создаёт обычного пользователя панели с новым логином,
который человек вводит локально через `prepare-user`. Агент получает только id заявки. Пароль генерируется внутри скрипта; логин и пароль
сохраняются до запроса в `~/.config/fastpanel/users/<аккаунт>/user-<суффикс>.json` (`600`).
Агент этот файл не читает; в `config.json` доступы автоматически не добавляются.
Правило `--owner` ниже относится к сайтам и базам, а не к созданию самого пользователя.

## Минимальный внешний отчёт

Перед изменением назови непрозрачный id аккаунта, id владельца/пользователя (или заявки)
и действие. Не запрашивай адрес панели ради отчёта. Общий вывод перед операцией содержит
только `status: "pending"` и, если выбран, `owner_id`.

Для пользователей и SSH ответы ограничены id, результатом операции и готовностью доступа;
списки аккаунтов — только непрозрачными id. Это строго проверенный JSON-контракт без
свободного текста: он не маскируется по совпадениям логинов, чтобы сохранять числовые id
и имена полей. Произвольные поля и значения через него не допускаются.

Во внешние сообщения включай лишь данные, необходимые для запрошенного действия.
Не дополняй ответ скрытыми полями из конфига, кеша, диагностики или старой переписки.
Данные сайтов, баз и DNS, необходимые для их выбора и проверки удаления, по-прежнему
выдаются соответствующими инструментами; это не универсальная фильтрация всех их полей.

## Владелец создаваемого (сайт, база, что угодно)

Скрипт сам смотрит, сколько пользователей панели видит аккаунт (`GET /api/users`):

- **один** (обычный пользователь панели) — создаёт от его имени, ничего не спрашивая;
- **несколько** (администратор панели видит всех; обычно его логин `fastpanel`, но
  определяется он и по роли `…ADMIN`) — без `--owner`
  ничего не создаёт: выходит с кодом **4**, выдаёт `code: "owner_required"` и `owner_ids`.
  **Спроси пользователя, от чьего имени создавать, инструментом вопроса; сам не выбирай.**
  `--owner` принимает только числовой id пользователя панели. Список заранее: `fastpanel_accounts.py users -A ID_АККАУНТА`.
- **от имени самого администратора панели (`fastpanel`) ничего не создаётся** — ни сайт, ни база, ни что-либо ещё;
  скрипт откажет, обхода нет.

Имена всех пользователей панели, включая администратора и пользователей вне конфига,
скрываются. В списках, выборе владельца и SSH-командах используются только числовые id.
Свободный текст ошибок сервера не выводится; при необходимости человек смотрит его
в панели локально. Имена в путях также скрываются — не пытайся их восстановить.

База всегда привязывается к сайту (`--site` обязателен), и сайт должен принадлежать тому же
пользователю панели, что и база, — скрипт проверяет это до создания и при расхождении
ничего не создаёт.

## Выбор аккаунта

1. `--account ID` из `list` или переменная `FASTPANEL_ACCOUNT` (локально также поддерживается name).
2. Аккаунт один — берётся он.
3. Несколько и у одного `"name": "default"` — берётся он.
4. Иначе код `account_required`: вызови `list` и предложи выбрать непрозрачный id. Спроси пользователя,
   молча не выбирай.
